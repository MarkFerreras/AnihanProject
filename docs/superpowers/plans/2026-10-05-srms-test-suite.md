# SRMS Test Suite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add ~170 JUnit test methods (~350 executed cases via parameterization) that prove the SRMS works correctly and can be cited as ISO/IEC 25010 evidence in the capstone paper.

**Architecture:** Tests only. Reuse existing patterns: `@WebMvcTest` + `@Import({SecurityConfig, GlobalExceptionHandler})` + `@MockitoBean` for controllers; plain Mockito for services; `@DataJpaTest` on H2 (`MODE=MySQL`) for repositories/integration; file-reading contract tests for schema and static frontend. Route/role coverage is generated by reflection over `RequestMappingHandlerMapping`, so it cannot drift from the controllers.

**Tech Stack:** JUnit 5 (+ `@ParameterizedTest`), Mockito, Spring Security Test, Spring Boot test slices, H2, JaCoCo (Task 0, needs approval).

**Spec:** None written. Scope was agreed in chat (2026-10-05): purpose = capstone evidence + verify the SRMS functions correctly; order = security → recovery → validation/data → business rules → measurement.

## Global Constraints

- Work only on a feature branch (current: `new-unit-tests`). Never commit to or push `main`.
- Production code is **not** changed. A test that fails because of a real defect is recorded under *Findings* in the task report and reported to the user; it is not silently fixed and not silently `@Disabled`.
- Stack stays Java 25 / Spring Boot 4.0.4 / Gradle Kotlin DSL / JUnit 5. No new test libraries. JaCoCo is the only build addition and only after approval.
- Test packages mirror main: `com.example.springboot.{controller,service,repository,integration,security,support}`.
- Every new test class gets a Javadoc line `ISO 25010: <characteristic>` (Functional suitability / Reliability / Security / Maintainability / Usability) used by Task 13 to build the evidence index.
- Memory bank (project rule): one bounded top-of-file entry in `progress.md`, `changeLog.md`, `testing.md` per **phase** (not per task) to save tokens.
- Existing baseline: 588 tests, 0 failures. It must still be 0 failures after every task.

## Token-Efficiency Rules (for the executor)

1. **Never read whole files.** `Grep` for signatures, then `Read` with `offset/limit` on the one class under test.
2. **Extend, don't duplicate.** If a test class for the target exists (see per-task "Extends"), append methods; read only its imports/fixtures (first ~60 lines).
3. **Parameterize.** One `@ParameterizedTest` row replaces a copy-pasted method; this is why ~170 methods yield ~350 cases.
4. **Run narrow, then wide.** Per step: `./gradlew test --tests "<Class>" -q`. Full `./gradlew test -q` only at the end of each phase. Read only failure lines, not the full log.
5. **One commit per task**, message `test: <task name>`; no per-step commits.
6. **No subagent per tiny task.** Recommended execution is *Native* for Phases 1–3 (shared helpers), optionally subagent-driven for Phase 4 where classes are independent.
7. **Verify before asserting.** Where the catalog says `(verify)`, run the endpoint/service once, read the real behaviour, then pin it. Do not guess status codes or messages.

## Review Focus

Failure modes the spec implies but no ordinary happy-path test exercises (each is pinned by a named test below):

1. `/api/lookup/**` is **not** listed in `SecurityConfig`, so it falls to `anyRequest().authenticated()`; a `PENDING_SETUP/VERIFICATION/RESET` session counts as authenticated. Expected by a reasonable person: no access. → `T1-09`.
2. Malformed JSON body reaches `handleGenericException` (500) unless Spring's `HttpMessageNotReadableException` is handled elsewhere. Expected: 400. → `T3-12`.
3. Non-numeric path/query values (`batchYear=abc`, `/classes/abc/students`) return 500 today (noted in `testing.md`). Expected: 400. → `T3-13`.
4. Reset step reused after the 15-minute window or after success. Expected: rejected, session invalidated. → `T4-10`, `T4-11`.
5. A second browser tab / replayed `verify` after lockout. Expected: still locked, no extra audit spam. → `T4-07`, `T4-08`.
